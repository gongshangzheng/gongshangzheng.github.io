## MODIFIED Requirements

### Requirement: 规划审批前提供基于问答的迭代阶段

内容类文章 change 在提交最终审批前 MUST 支持围绕文章核心内容进行 Q&A 迭代。用户提出的问题应基于素材和原文回答；若答案改变或细化文章的问题定义、解法概述、解释深度、内容取舍或结构，MUST 将相应结论回写到 design 的速览、大纲、Decisions 或 Risks，并重新呈现受影响部分。与文章规划无关的纯答疑无需强行写入 artifact。只有用户确认整体规划后才能进入正文写作。

#### Scenario: 用户通过提问澄清论文方法

- **WHEN** 用户在确认文章 change 前询问论文机制、训练方式或损失函数
- **THEN** agent 先依据原文回答；若回答影响文章主线或讲解安排，则更新 design 并再次请用户审阅，不直接开始写正文

### Requirement: 内容类 change 先提供核心问题与解法速览

内容类 change 的 design MUST 在完整「文章内容大纲」之前提供简明的核心问题与解法速览，至少包含：要解决的问题、作者的解决办法、核心思想、具体机制。论文精读的速览 MUST 为事实性陈述提供原文定位；原文定位用于追溯依据，不代表内容尚未核验。只有尚未对照原文、来源不清或证据不足的具体主张才 MUST 标注待核验。具体机制概述 MUST 区分论文陈述与编辑归纳，不得将代理标签、训练假设或有限实验结果夸大为模型对真实风格的精确识别能力。

#### Scenario: 审阅论文精读规划

- **WHEN** 用户打开一篇论文精读的 design
- **THEN** 在逐节大纲前即可读到问题、作者解法、核心思想和具体机制的简述，并可根据原文定位判断概述是否可信

### Requirement: 计划先交代问题、动机与现有方法缺口

论文精读的写作规划 MUST 在展开方法细节前，先用可回溯到论文原文的素材说明：论文要解决的具体问题、问题的重要性或难点、以及现有方法的具体缺口。该问题陈述是阅读理解的起点，不得仅凭标题、方法名称或作者的宣传性贡献表述推断；证据不足时 MUST 标记待核实并回读原文。

#### Scenario: 规划论文精读文章

- **WHEN** agent 在 change 中规划论文精读的章节骨架
- **THEN** 引言/问题剖析先呈现问题—动机—缺口及原文指针，之后才规划方法拆解；证据不足的部分明确列为待核实

### Requirement: 规范单一事实来源且各 skill 只保留指针

门禁流程（触发条件、模板位置与填法、审批门禁、豁免清单、写作规划的位置）MUST 集中维护在库内 `~/gongshangzheng.github.io/.agents/skills/blog-rules/references/openspec-gate.md` 一处；七个内容类 skill MUST 各自只保留简短的门禁小节并指向该文件（用库内锚定路径，不得写 `~/.agents/skills/`），不得复制流程正文。门禁小节的位置 MUST 在该 skill 的**素材/分析产出之后、写作之前**（`read-article` 为 Phase 4；其余 skill 位于其管线的规划节点）——没完成素材与分析写不出有内容的写作规划。文章的写作规划 MUST 写在 change 的 `design.md`（「文章内容大纲」节），MUST NOT 另建规划草稿之类的中间文件。

#### Scenario: 修改门禁流程

- **WHEN** 需要调整门禁的触发条件、模板填法或豁免范围
- **THEN** 只修改 `blog-rules` 下的共享层文件即可对所有内容类 skill 生效，不存在需要同步的多份副本

#### Scenario: agent 按 skill 执行内容任务

- **WHEN** agent 读取任一内容类 skill 并完成其素材/分析阶段
- **THEN** 在该 skill 的素材与分析产出之后、写作之前存在门禁小节，agent 据此读取共享层规范、建 change 并在 `design.md` 中写出写作规划

#### Scenario: 写作规划落在 change 里

- **WHEN** agent 为某篇待写文章规划章节结构、素材来源与图表公式
- **THEN** 该规划写在 `openspec/changes/<slug>/design.md` 的「文章内容大纲」中，仓库里不出现独立规划草稿文件；论文精读的大纲先说明问题—动机—缺口及原文指针；用户对该 change 的确认即为"批准写作规划"
