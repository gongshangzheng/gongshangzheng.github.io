## Goals / Non-Goals

**Goals:**
- 让读者能从图形化客户端开始，完成一个低风险的 Agent 初次任务。
- 说明 CC Switch 管理供应商的直连、路由和聚合模式，并重点讲清 Codex 与上游协议不匹配时的处理思路。
- 解释规则文件、Skills 和提示词的用途边界及第三方 Skill 的安全风险。
- 对版本敏感的 UI、平台可用性和配置字段在写作前核对官方文档与实测，正文注明版本/日期。

**Non-Goals:**
- 不写成 Codex、Claude Code、Pi 的全面横向测评，也不把 Codex 宣称为所有新手的唯一或绝对最佳选择。
- 不推荐特定 API 中转商，不承诺其价格、稳定性、模型质量或合规性。
- 不展开 Pi 的完整教程，不在本 change 中修改 Agent 工具配置或执行生产环境操作。
- 不把“这篇写给谁”作为文章中的独立章节；读者定位只作为内部规划约束。

## 核心问题与解法速览

- **问题是什么？** 初次使用 Agent 的读者需要同时理解客户端入口、模型账号/API 配置和可扩展指令，配置链路容易被终端操作或协议不兼容卡住。库内已有 Agent 概念与 Harness 文章，但缺少从桌面客户端到后端切换的连续操作教程。
- **文章提出的解决路径是什么？** 先比较常见 Agent 并推荐以 Codex 入门；再用 CC Switch 为 Codex 配置/切换可用模型供应商；随后完成一个受控任务，并介绍项目指令、Skill 与提示词的使用。具体操作须在写作前按当前版本复核。
- **核心思想（编辑归纳）**：Agent 入门不是只选一个模型，而是理解客户端、模型服务、项目指令与技能扩展之间的分工。教程以一条可回退的实践路径组织，不把单一工具推荐泛化到所有用户。
- **具体机制（现有文档依据）**：CC Switch 用户手册称其本地路由会在本机接收 Codex 请求，并可将 Responses 请求与 Chat Completions 或 Anthropic Messages 上游格式转换。指南给出的默认本地地址为 `127.0.0.1:15721`，示例版本要求 CC Switch 3.17.0+；这些版本与字段须在写作时重新核验，不能假设所有供应商/模型均兼容。

## Decisions

- 采用 Codex App 作为**操作示例**，而不是将它写成对所有用户的唯一推荐；这样保留用户提出的低门槛入口，同时避免把个人偏好包装成普遍结论。
- CC Switch 的配置和供应商切换集中在第二章；协议兼容作为同章内的条件分支说明，Skills 不在该章展开，避免把同一配置工具拆成重复章节。
- “这篇写给谁”只作为本文件的服务对象字段，不在文章中设置读者画像章节。
- 不引用未核实的搜索跳转链接；发布前尽量换成官方原文和教程原始 URL，并记录核查时间。

## Risks / Trade-offs

- [产品能力和 UI 随版本变化] → 文章标注核查日期/版本；写作前以官方文档及当前 App 复核，易变步骤避免写死截图外的字段。
- [协议转换不等于所有模型都能正常工作] → 说明上游协议、模型/工具调用能力及供应商限制；将实测范围写清，失败时提供回退路径。
- [第三方中转存在隐私、稳定性、计费与条款风险] → 不推荐商家、不输入敏感代码做测试；提醒读者查看服务条款和数据处理方式。
- [桌面 App 与 CLI 的配置行为可能变化] → 不把本机配置观察表述为普遍保证；在当前版本复测或只引用官方支持文档。
- [主题与既有 Agent/Harness 文章部分重叠] → 本篇聚焦具体使用与配置步骤，理论背景只做必要链接，不复述既有长篇内容。
