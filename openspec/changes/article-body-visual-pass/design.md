## Context

`site-visual-quality` 已经把框架层的可读性下限写成了可验证的约束，上一轮 `impeccable-site-pass` 修掉了首页、索引页、Hub 与日报。这次把扫描面扩到文章正文，发现同一批缺陷换了一种载体：正文组件（信息块、定义块、提示块、示例块、callout）的标题色在亮色主题下 2.0–4.1:1，以及正文标题大纲的系统性跳级。

标题跳级的规模决定了修法：570 个页面（占全站 813 个内容页的 70%）是 `h1` 后直接 `h3`，其中 526 个整页没有 `h2`。原因是站点写作习惯——`###` 当节、`####` 当小节。逐篇改 `src/pages/` 正文等于重排 570 篇文章的结构，改动面与风险都不成比例。

约束：`lib/toc.js` 已经在构建期重写每个标题的 `id` 与样式类（`h2`→`.ch-title`、`h3`→`.section-title`、`h4`→`.ch-section`），并且排除了一批容器（数学公式等）。任何标题归一都必须与这套既有机制共存，且不能把导航或侧栏的标题算进去。

## Goals / Non-Goals

**Goals:**

- 570 个正文页在构建后大纲合法，且节标题的字号、颜色、下划线逐项保持原样。
- 正文组件的标题色在两套主题下都过 4.5:1；组件内边距、嵌套容器、行内数学字号三处按同一套下限收口。
- 判据写回 `site-design-language`，下一轮再扫正文组件时不需要重新推导。

**Non-Goals:**

- 不改 `src/pages/` 的正文内容与作者写法（`###` 仍然是作者可以写的节标记）。
- 不调整正文组件的配色基调（仍用 `--accent-gold` / `--accent-blue` / `--accent-red`，只改混合比例）。
- 不处理 advisory 噪音（`straggler`、`unbalanced-heading`、`em-dash-overuse`）。
- 不动 `shape-assembled-illustration` 覆盖的图示本身，只把它登记为设计选择。

## Decisions

**D1 标题归一放在构建期，而不是批量重写 570 个源文件。**

在 `lib/toc.js` 的 `processHeadings` 里，先解析正文容器（`.wrap` / `.main-content`）内的标题序列，算出归一偏移 `shift = 首个正文章标题层级 - 2`（仅当首个层级 > 2 时非零），再对每个标题输出 `max(2, 原层级 - shift)` 作为标签层级。样式类仍按**原层级**映射，所以 `.ch-title` / `.section-title` / `.ch-section` 的取用不变，视觉零位移。

实施时发现偏移不能只看「非排除容器内的标题」：370 个页面的节标题其实写在卡片组件里（`info-box` 199 + `paper-info` 46 + `def-box` 50 + `sources` 31 + `callout` 6 + `example-box` 6），这些标题本来就被 TOC 排除、不参与大纲，但检测器按 DOM 顺序看到 `h1` 后紧跟这些 `h3`，照样判跳级。所以偏移改为按**文档中第一个 `h2`–`h6`（含组件内部标题）**计算：`shift = max(0, 首个标题层级 - 2)`，并把同一偏移作用到被排除容器内部的标题上（它们仍然不进 TOC，只改标签）。这样两类页面用同一条规则收口。

连带的代价是组件标题标签升级后要补 `h2` 镜像样式，见 D8。

被否的备选：

- 批量改 `src/pages/*.html` 的 `###` → `##`：570 个文件、2300+ 处标签改动，且会让作者下次写 `###` 时再次漂移；`h4 → h3` 的连带升级又会改变 `.ch-section` 的取用，视觉必然变。
- 只写 lint 门禁不加归一：门禁会立刻报 570 个页面失败，等于把问题原地冻结。

**D8 组件标题被提升为 `h2` 后，组件样式补 `h2` 镜像。**

`.info-box h3`、`.def-box h3`、`.callout h3`、`.example-box h3`、`.theorem-box h3`、`.sources h3` 这些选择器是「标签 + 类」写法，标签变成 `h2` 后不再命中，`.wrap h2` 的通用排版会接管，字号与边框都会变。做法是把每条组件标题选择器同时覆盖 `h2` 与 `h3`（`h2` 在前，保证被升级的标题与未升级的标题一致）。这比在每个组件上写 `[data-outline-from]` 例外更容易读，也不依赖构建期属性。

被否的备选：用 `data-outline-from="3"` 属性统一写「按原层级排版」的补偿规则——属性语义隐晦，且组件样式分散在三个模块里，最终还是得逐个组件对照。

**D2 组件标题色用「强调色 × 文字色」的混合比例重新配平，不换色相。**

现有写法已经用了 `color-mix`，只是比例不够：`info-box` 是 `accent-gold 75% + text-heading`（亮色 3.2:1）、`callout` 直接用 `accent-red`（2.0:1）。按上一轮 `.ch-label` 的验证结果，把强调色占比压到 45–55% 区间、其余补 `--text-heading`，亮色下可到 4.5–5.5:1，暗色下更高（暗色文字色本身是浅色，混合方向相反但同样提升对比）。

实施时发现偏移不能只看「非排除容器内的标题」：370 个页面的节标题其实写在卡片组件里（`info-box` 199 + `paper-info` 46 + `def-box` 50 + `sources` 31 + `callout` 6 + `example-box` 6），这些标题本来就被 TOC 排除、不参与大纲，但检测器按 DOM 顺序看到 `h1` 后紧跟这些 `h3`，照样判跳级。所以偏移改为按**文档中第一个 `h2`–`h6`（含组件内部标题）**计算：`shift = max(0, 首个标题层级 - 2)`，并把同一偏移作用到被排除容器内部的标题上（它们仍然不进 TOC，只改标签）。这样两类页面用同一条规则收口。

连带的代价是组件标题标签升级后要补 `h2` 镜像样式，见 D8。

被否的备选：给组件标题单独定义一组 `--tone-*-title` 变量——现有变量够用，多一组变量等于给后人再开一个漂移口。

**D3 `.admonition` 的内边距用 `:not(:has())` 判定，只补裸写法。**

`169` 个页面用 `.admonition`，其中一部分用 `.admonition-content` 承载正文（已有 1em 内边距），另一部分直接放 `<p>`（0 内边距，实测文字贴 1px 边框）。`padding` 加在 `.admonition` 上会让前一种变成双层缩进，所以用 `.admonition:not(:has(> .admonition-content)) { padding: 1em; }`。`:has()` 目标浏览器（Chrome/Safari/Firefox 2023 起）都支持，站点的构建产物只面向现代浏览器。

**D4 组件内 `.table-wrap` 去掉边框与圆角。**

`.table-wrap` 自带 `border: 1px solid` + `border-radius: 8px`，放进已经是卡片的 `.example-box` / `.info-box` 里就成了卡片套卡片。改为在这类组件内部时不画边框与圆角，横向滚动由 `.table-scroll` 承担，功能不受影响。实施时发现偏移不能只看「非排除容器内的标题」：370 个页面的节标题其实写在卡片组件里（`info-box` 199 + `paper-info` 46 + `def-box` 50 + `sources` 31 + `callout` 6 + `example-box` 6），这些标题本来就被 TOC 排除、不参与大纲，但检测器按 DOM 顺序看到 `h1` 后紧跟这些 `h3`，照样判跳级。所以偏移改为按**文档中第一个 `h2`–`h6`（含组件内部标题）**计算：`shift = max(0, 首个标题层级 - 2)`，并把同一偏移作用到被排除容器内部的标题上（它们仍然不进 TOC，只改标签）。这样两类页面用同一条规则收口。

连带的代价是组件标题标签升级后要补 `h2` 镜像样式，见 D8。

被否的备选：给表格容器加 `box-shadow` 区分层级——那只是把嵌套换个说法。

**D5 行内数学字号抬到下限，先量后定。**

MathJax 行内渲染的 `mn` 实测 10.64px。`mjx-container` 没有显式 `font-size`，只靠 MathJax 自身的缩比。做法是给 `.math-inline mjx-container` 一个略大于 1 的相对字号，构建后实测确认 ≥11px，同时检查行内公式的基线对齐（`vertical-align: -0.15em`）没有跳行。若抬字号导致行距抖动，退回「登记为检测器噪音」而不是硬改。

**D6 `shape-assembled-illustration` 登记为设计选择。**

站内图示是用矩形、箭头、文字拼出来的 SVG 结构图（架构图、流程图），而这条规则针对的是用几何形状拼贴冒充插画的假图。写入共享 ignore，理由记进 `site-design-language` 的检测器基线小节——与上一轮的 `side-tab`、`em-dash-overuse` 同一处理方式。

**D7 验证沿用上一轮的回路，并新增两个面。**

扫描面在原有 8 个之外，加 4 个正文页（历史叙事、论文精读、语言课笔记、多模态论文页），它们分别代表 `callout`、`info-box`/`def-box`、`example-box`、`admonition` 四种组件。暗色主题继续用探针页注入 `localStorage theme=dark` 复核。

## Risks / Trade-offs

- 标题归一作用在 570 个页面上，一旦偏移算错会连带改掉视觉。 → 归一前后各取 3 个代表页（历史叙事、论文精读、课程笔记）逐项比对节标题的计算样式；`classMap` 按原层级取用是这条保障的核心，不允许改成按新层级取。
- `.admonition:not(:has(...))` 在极老浏览器上整条规则失效，裸写法继续贴边。 → 站点已弃用旧浏览器（构建产物用 `color-mix`、`:has` 同代特性），失效时只是回到现状，不会更差。
- 组件标题色调整会让 879 处引用整体变深。 → 只改混合比例、保留色相；抽查 4 个组件代表页确认仍是暖金/蓝/红调。
- 行内数学放大可能影响行距。 → D5 已设回退路径。
- 归一化会改变 TOC 侧栏的层级深度（`h3` 现在算 `h2`）。 → 侧栏本来就按层级嵌套，深度变化后仍是一棵合法树；构建后抽查两个长文页的侧栏折叠层级。

## Migration Plan

1. 全部改动在构建期与 CSS 层，无数据迁移。
2. `node tests/run.js` + `node build.js` 后复扫 12 个面（8 旧 + 4 新），暗色复扫 3 个面。
3. 回滚：`lib/toc.js` 与 CSS 分别 `git checkout --`；归一化的开关如果需要临时关掉，`shift` 计算处保留一个显式的 `if` 分支即可。
