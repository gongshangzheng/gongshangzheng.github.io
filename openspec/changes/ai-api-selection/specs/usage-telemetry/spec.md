# usage-telemetry

## Purpose

采购落地后持续统计课题组各成员、各场景、各模型的 token 消耗与费用，让档位复核和加购决策有数据可依。

## ADDED Requirements

### Requirement: 分层多源采集
管道 SHALL 按三层采集用量：①供应商提供用量/余额 API 的自动拉取；②控制台可导出但无 API 的，支持手动导出文件导入；③客户端 harness 本地日志导出兜底。每条用量记录 SHALL 归一化为统一结构：成员、供应商、模型、场景标签、token 数（输入/输出/缓存分列，可得时）、费用、时间戳、采集层来源。

#### Scenario: 供应商无用量 API
- **WHEN** 某供应商不提供用量 API 但可从控制台导出记录
- **THEN** 该供应商数据经手动导出导入进入统一结构，来源标记为手动层，不阻塞其他来源

### Requirement: 场景打标
用量记录的场景标签 SHALL 通过"工作目录/项目 → 场景"映射表自动生成（初始场景：研究、写文档）；映射表 SHALL 可由用户编辑；无法映射的记录 MUST 标注 `UNTAGGED` 而非猜测归类。

#### Scenario: 按目录自动打标
- **WHEN** 导入的用量记录带工作目录信息且命中映射表
- **THEN** 该记录自动获得对应场景标签；未命中的记录标为 `UNTAGGED`

### Requirement: 隐私边界
管道 MUST NOT 采集、存储或上传提示词与回复内容；仅允许上述统一结构中的统计字段。

#### Scenario: 客户端日志导出
- **WHEN** 从客户端 harness 日志提取用量
- **THEN** 导出结果仅含统计字段，不包含任何消息正文

### Requirement: 周期报告与复核联动
管道 SHALL 生成月度用量报告：按成员、场景、模型汇总 token 与费用，并与当前套餐档位对比给出"够用/超量/冗余"提示；报告 SHALL 与采购决策的 30 天 `STALE` 复核机制联动。

#### Scenario: 月度报告生成
- **WHEN** 月内存在至少一个采集来源的数据
- **THEN** 报告按成员/场景/模型三维度汇总，并附套餐适配提示
