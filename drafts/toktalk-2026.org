* TokTalk：Audio-LLM token 驱动的 FLAME 参数空间实时面部动画（flow matching）
** 基础信息（2026-09-01 调研）

- arXiv 2605.31294，2026-05，University of Toronto
- 任务：Audio-LLM token → 实时 FLAME 面部动画（语音合成与动画生成并行）
- 工作空间：FLAME 参数空间（expression/jaw/neck pose 系数），用 flow matching 生成——扩散的近亲，仍是运动空间路线

** 原理

- 输入不是原始音频，而是 Audio-LLM（Mimi / CosyVoice2 / GLM-4-Voice 三种 token 体系均可）的离散 speech token embedding
- 轻量对齐模块把 token embedding 对齐给 chunk 化 flow decoder：因果 block-causal attention 的 1D U-Net 式 Transformer（12 个中间 block，每 stage 8 注意力头）
- 动画生成与语音解码流水线并行执行，动画计算被语音解码时间隐藏 → 首帧延迟约 400ms
- chunk 尺寸（0.4s/0.8s/1.2s）与 flow 步数（1-20）可调，动画推理 26-187ms

** 训练配置

- 单张 L40S GPU，base model 训练 144 小时——非常轻量
- 数据：HDTF + TFHP 合并，约 26.5 小时、588 个身份

** 效果对比

- 基线是 3D 面部动画方法（DiffPoseTalk / MSMD / FaceFormer / EmoTalk），没有直接对比 Ditto / EMAGE（任务输出不同：FLAME 系数 vs talking head 视频）
- TokTalk(style)：MSE 1.39，LVE 14.53，FDD 4.29，MOD 2.82mm
- DiffPoseTalk 离线模型 MSE 1.33 / LVE 13.64 略优，但 TokTalk 是实时的——以极小代价换实时
- 卖点：动画不增加语音首包延迟（400ms 即语音本身延迟），任意 Audio-LLM 可换

** 与 Ditto/AvatarForcing 的关系

- 引用 Ditto 作为"2D 扩散路线"的先前工作；未提 AvatarForcing
- 定位：Ditto 的"音频特征→运动"换成"Audio-LLM token→运动"，走 LLM token 化路线
