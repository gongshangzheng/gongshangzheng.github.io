* Agent 使用教程

** 核心问题

新手上手 AI 编程 agent 的两个卡点：

1. **选哪个、怎么装**——终端、API key、代理，任何一项都能劝退。
2. **怎么换模型后端**——尤其是 Codex 用国产模型：Codex 客户端使用 OpenAI Responses API，而不少国产模型服务只提供 Chat Completions；**只改 base_url 可能收到 404**，这一层协议差异常被忽略。

本文主张：新手从 **Codex 桌面 App** 起步（不碰终端、一个账号登录），用 **CC Switch** 换国产后端（图形界面，不手改 TOML）。

** 大纲

*** 1. 为什么新手从 Codex App 而不是终端开始

- 主流三选一速览：Codex（有桌面 App）/ Claude Code（终端为主）/ pi（开源、可换模型）
- 推荐 Codex App 的理由：图形界面、一个账号登录、不用碰 CLI
- 诚实说清取舍：桌面 App 省事但可调项少，要精细控制时再换
- 三种入口的关系：桌面 App / CLI / Cloud，新手先用哪个

*** 2. 装 Codex App + 跑通第一个任务

- 下载安装（macOS / Windows / Linux；Windows 走微软商店或 winget）
- 账号登录
- 第一个任务怎么提（要能立刻看到结果）
- 动手前先 git commit——它真的会改你的文件

*** 3. 装 CC Switch：一键换供应商

- 解决什么：换供应商不用手改 JSON / TOML / YAML
- 安装（ccswitch.io / GitHub Releases）
- **首次启动自动把现有配置导入为 `default` 供应商，原配置不丢**（消除"会不会搞坏"的恐惧）
- 三种模式：**直连** / **路由** / **聚合**
- 生效方式：**Codex 改完必须重启**，新手最容易以为"没生效"
- 系统托盘快速切换

*** 4. 给 Codex 换国产后端（本文最有价值的一节）

- **先讲清协议坑**：Responses API vs Chat Completions vs Anthropic Messages，为什么不能只改 base_url
- **路线 A：CC Switch 路由模式**（首选）
  1. Codex 页签 → 加供应商（自定义）
  2. 填名称 / API Key / 请求地址 / 默认模型
  3. 高级选项 → 「上游格式」选 Anthropic Messages 或 Chat Completions（需开启路由）
  4. 切到「路由」标签 → 点「开始路由」
  5. 重启 Codex → 验证
- **路线 B：本地协议翻译代理**（兜底）
  - 架构：Codex App → cc-switch → 本地代理 :11435 → DeepSeek
  - 三个关键字段：`wire_api=responses`、`requires_openai_auth=true`、API 地址指向本地端口
  - 健康检查 `curl http://127.0.0.1:11435/health`
- 国产后端选项盘点：DeepSeek / Kimi / GLM / Qwen / 各类中转站（中立列举，不推荐具体商家）
- **怎么切回官方**：启用 OpenAI Official 供应商
- 坑：CC Switch 里 config.toml 被重置（GitHub issue #1863）

*** 5. 三个概念别搞混（跨工具通用）

| 放什么 | 放哪 | 何时进上下文 |
|---|---|---|
| 长期规则 | `AGENTS.md` | 每次请求 |
| 做事的流程 | Skill | 用到才读全文 |
| 常打的一段话 | 提示词 | 敲 `/名字` 时 |

- Codex 认 `AGENTS.md`；给一个最小例子

*** 6. 怎么用 Skill

- 是什么：按需加载的能力包，启动时只放 name + description（progressive disclosure）
- 从哪来：内置、社区、自己写
- **CC Switch 自带 Skills 管理**：侧栏「Skills」→「发现技能」→ 搜 skills.sh 或 GitHub → 一键安装到支持的工具
- 怎么自己写一个最小 SKILL.md（照抄一个例子）
- **安全提醒**：skill 能让模型执行任意动作、可含脚本，用前先读

*** 7. 新手常见坑清单

- 没 commit 就让 agent 改代码
- API key 写进代码 / 提交进 git
- 改完供应商没重启 Codex，以为没生效
- 只改 base_url 就想让 Codex 用国产模型（协议不兼容）
- 一次装十个 skill 互相打架
- 用小众中转站导致模型被"注水"

*** 8. 进阶：什么时候考虑换 pi

- 触发信号：被单一厂商锁住 / 想省钱换模型 / 想要跨 harness 复用的 skill / 想自托管
- pi 的优势：模型可换、skill 格式通用（Agent Skills 标准）、可自托管
- **CC Switch 也支持 Pi**，迁移成本比想象中低

** 关键素材

*** 本机实测（2026-10-10，这些是本人在用的环境，可直接当一手证据）

- **本机 Codex App 配置指向 `~/.codex/`**：本机 `/Applications/Codex.app`（v26.609.71144）对应的 `~/.codex/config.toml` 中有 `model_provider = "custom"` 和 `[model_providers.custom]`；`mcp_servers.node_repl.env` 中的 `CODEX_CLI_PATH` 指向 App 包内的 Codex 可执行文件，`CODEX_HOME` 指向 `~/.codex`。这支持 App 使用该配置目录；正文中仍应以 Codex 官方文档核对配置路径，不把本机观察泛化成所有版本行为。
- **第三方 Responses 兼容中继可直接用**：本机 config.toml 里 `base_url = "https://api.asxs.top/v1"`（非官方）+ `wire_api = "responses"` + `requires_openai_auth = true` 已经在跑。这个三字段组合就是接第三方后端的标准写法。
- **CC Switch v3.20.3 已装**，配置在 `~/.cc-switch/`：`cc-switch.db`（SQLite）、`settings.json`、每天一份 `backups/db_backup_*.db`、以及自己的 `skills/` 目录。
- CC Switch `settings.json` 里可引用的字段：`enableLocalProxy: true`（本地路由）、`currentProviderCodex`、`preserveCodexOfficialAuthOnSwitch`、`skillSyncMethod: "auto"`、`skillStorageLocation: "cc_switch"`、`visibleApps.codex`。
- **Codex 有自己的 skills 目录**：`~/.codex/skills/`（本机装的是 hyperframes 系列）。
- 本机 `~/.codex/AGENTS.md` 存在（目前为空）——Codex 认 AGENTS.md。

*** 协议坑（官方文档原文）

摘自 cc-switch `docs/guides/codex-claude-routing-guide-zh.md`：

> 新版 Codex CLI 面向的是 OpenAI Responses API，而各类 Claude 系中转网关、企业内部网关暴露的是 Anthropic Messages 协议……把这类网关的接口地址直接填进 Codex 配置里，结果只能是请求 `/responses` 返回 404。

摘自 cc-switch 用户手册 `4.1-service.md`：

> 转换接口格式：让 Claude Code 使用 OpenAI 或 Gemini 格式的供应商，让 Codex、Grok Build 使用 Chat Completions 或 Anthropic Messages 格式的供应商

→ 这就是「CC Switch 能直接给 Codex 换国产后端」的官方依据，不一定需要额外的翻译代理。

*** CC Switch 路由的工作机制（可直接写进文章）

1. Codex 接管时，本地配置被写成 `http://127.0.0.1:15721/v1`，并**强制保持 `wire_api = "responses"`**
2. 供应商的上游格式（`anthropic` / chat 等）告诉路由：真实上游说什么协议
3. 路由把 `/responses` 改写到 `/v1/messages`（或 chat 端点），并把请求体转换
4. 上游返回后，再把 JSON/SSE 转回 Codex 能懂的 Responses 形态（推理内容、工具调用、图片都在转换范围内）

额外要点：

- 本地路由默认监听 `127.0.0.1:15721`，可在「设置 → 本地路由 → 服务」改。
- 支持本地路由的应用：Claude Code、Codex、Gemini CLI、Grok Build。
- `Anthropic Messages 上游` 需要 **CC Switch 3.17.0+**。
- **真实 Key 只存在 CC Switch 里，由路由转发时注入，不进 Codex 的 live 配置**——这是个好的安全论述点。
- 路由模式还附带**自动故障转移**：当前供应商请求失败时按队列切换备用供应商。
- 「直连 / 路由 / 聚合」标签点一下只是**查看**，真正切换要点标签下的按钮（「开始路由」/「切换到聚合模式」/「回到直连」）——新手极易踩这个坑。

*** CC Switch 其余可用事实

- 侧栏工具：Claude Code / Claude Desktop / Codex / Gemini CLI / Grok Build / OpenCode / OpenClaw / Hermes Agent / **Pi** / MiniMax Code
- 首次启动会自动把现有配置导入为名为 `default` 的供应商，并为这几个工具添加官方供应商，**原有配置不会丢失**
- 授权中心（Beta）：可把 GitHub Copilot / ChatGPT / xAI 订阅当供应商用（除 Codex 的 OpenAI Official 外都需路由模式）。**需提示：在官方客户端以外使用订阅可能违反厂商条款，自行评估风险**
- 聚合模式：多家供应商的模型进同一个模型列表；**不提供故障转移**；Codex 的聚合列表变化后需重启
- 系统托盘一行一个工具，显示「名称 · 模式 · 供应商 · 额度」
