Part 1
研究范围：S2V 生成缺的不只是模型，还有基础设施

Subject-to-Video（S2V）生成指以参考主体图像（人、物、实体）为条件生成视频。2024-2025 年闭源（Kling 1.6、Pika 2.1、Vidu 2.0、Hailuo S2V-01）与开源（VACE、Phantom、SkyReels-A2、HunyuanCustom、ConsisID、Concat-ID、EchoVideo 等）模型并行爆发，但评测和训练数据两端的基础设施严重滞后——这是北京大学深圳研究生院 Li Yuan 组（PKU-YuanGroup，即 ConsisID 团队）在本文要解决的问题 #Yuan-et-al.-2025#。

论文给出 S2V 模型的三个核心挑战（也是整个 benchmark 设计的靶子）#Yuan-et-al.-2025#：

  1. 泛化差（Poor generalization）：训练分布外的主体类别上表现差——比如只训过西方人脸的模型对亚洲人脸明显更弱；
  2. 复制粘贴问题（Copy-paste issue）：模型直接把参考图的姿态、光照、轮廓搬进视频，而不是"理解主体后再生成"，结果一致性分数很高但人眼觉得很假；
  3. 人类保真不足（Inadequate human fidelity）：所有模型（包括闭源）对人类身份的保持都系统性弱于对非人实体的保持。
对身份一致性 survey 的意义：第 2、3 条挑战直接命中主 survey 的痛点——copy-paste 说明"一致性高"不等于"身份保持好"，而人类保真弱于非人实体是身份度量研究必须解释的现象。OpenS2V-Nexus 是把这两个问题制度化地暴露出来的 benchmark。

双件套构成：(i) OpenS2V-Eval——180 prompt、七类任务、六维指标的细粒度 benchmark；(ii) OpenS2V-5M——5.4M 高质量 720P 主体-文本-视频三元组，含 0.35M 反捷径设计的 Nexus Data #Yuan-et-al.-2025#。

Part 2
评测维度 taxonomy：七类任务 × 六个维度

2.1 七类任务分类

OpenS2V-Eval 把 S2V 拆成七类，覆盖单主体到多主体、人脸到任意实体 #Yuan-et-al.-2025#：

编号任务类别样本数说明
①single-face-to-video30单人脸 → 视频
②single-body-to-video30单人体 → 视频
③single-entity-to-video30单实体（任意物体）→ 视频
④multi-face-to-video15多人脸 → 视频
⑤multi-body-to-video15多人体 → 视频
⑥multi-entity-to-video30多实体 → 视频
⑦human-entity-to-video30人 + 实体混合 → 视频

180 对测试样本 = 80 真实 + 100 合成。来源配额：ConsisID 借 50 对、A2 Bench 借 24 对（构建 ①②⑦）；DreamBench 30 张参考图 + GPT-4o 写 caption（构建 ③）；其余从版权免费视频（Pexels/MixKit/PixaBay）出发，用 GPT-Image-1 从视频帧提取主体图、GPT-4o 写视频 caption。每个样本的参考图不超过 3 张（受现有 S2V 模型输入能力限制），全部人工收集以保证质量 #Yuan-et-al.-2025#。

图 1：OpenS2V-Eval 七类任务的示例（视频由 Kling 生成）。从单人脸到人+实体混合，类别设计覆盖 S2V 的全部输入组合（来源：Yuan et al., 2025, Fig.2）。

2.2 六个评测维度

评测框架的六维是本文最重要的 taxonomy 贡献——它把"主体好不好"拆成三个 S2V 专属维度 + 三个通用视频维度 #Yuan-et-al.-2025#：

维度指标类型计算方式
主体一致性 Subject ConsistencyNexusScore新建YOLO-World 检测裁剪 + GME 检索模型算相似度
主体自然性 Subject NaturalnessNaturalScore新建GPT-4o 五点量表打分
文本相关性 Text RelevanceGmeScore新建GME 多模态检索模型（长文本友好）
人脸相似度 Face SimilarityFaceSim-Cur借用（ConsisID 协议）insightface 检测 + CurricularFace 特征空间
视觉质量 Visual QualityAestheticScore借用improved-aesthetic-predictor
运动幅度 Motion AmplitudeMotionScore借用OpenCV OpticalFlowFarneback
图 2：OpenS2V-Eval 构建管线。左侧为测试样本构建（真实图 + GPT 合成图），右侧为评测体系——三个新建指标（NexusScore / NaturalScore / GmeScore）加三个借用指标（来源：Yuan et al., 2025, Fig.3）。

任务分组协议：由于不同模型支持的主体数量不同，评测拆成三组——Open-Domain S2V（全七类）、Human-Domain S2V（仅 ①②，且只输入人脸图像）、Single-Domain S2V（①②③，适配 HunyuanCustom 等只开源了单主体权重的模型）#Yuan-et-al.-2025#。

2.3 总分聚合协议

六个指标量纲不同，作者先做归一化：有界指标直接用理论范围（FaceSim-Cur 与 GmeScore ∈ [0,1]，NaturalScore ∈ [1,5] 的 Likert 量表），无界指标用经验分布截断（NexusScore ∈ [0, 0.05]、AestheticScore ∈ [0,1]、MotionScore ∈ [4,7]）。然后加权求和 #Yuan-et-al.-2025#：

\[ \text{Total\_Score} = \sum_{i \in \mathcal{M}} w_i \cdot S_i, \quad \mathcal{M} = \{\text{Nexus}, \text{Natural}, \text{Gme}, \text{FaceSim}, \text{Aesthetic}, \text{Motion}\} \]

Open-domain 权重：Nexus 0.20、Natural 0.24、Gme 0.12、FaceSim 0.20、Aesthetic 0.12、Motion 0.12；Human-domain 任务把人脸和自然性权重调高：Natural 0.30、Gme 0.15、FaceSim 0.25、Aesthetic 0.15、Motion 0.15 #Yuan-et-al.-2025#。

Part 3
身份/主体维度的定义与协议：NexusScore 怎么算

3.1 NexusScore：检测 + 裁剪 + 多模态检索

这是本文对"主体一致性怎么评"的核心回答。先看被批判的旧做法：VBench 系（以及继承它的 A2 Bench、VACE-Bench）直接计算未裁剪的视频帧与参考图像在 DINO 或 CLIP 空间的相似度。两个问题：背景被一起算进去（背景噪声），且 DINO/CLIP 特征空间本身已被 T2VScore、FETV、ChronoMagic-Bench 等工作证明不合理 #Yuan-et-al.-2025#。

NexusScore 的四步协议 #Yuan-et-al.-2025#：

第一步，检测。用图像提示检测模型 YOLO-World，以参考图 \(R_i\) 为 prompt 在视频帧 \(I_t\) 中定位对应主体，得到 bounding box：

\[ B_{i,t} = \mathcal{M}_{\text{detect}}(R_i, I_t) \]

第二步，裁剪。按 \(B_{i,t}\) 裁剪参考图得到 \(C_{i,t}\)，然后算裁剪参考图与实体名称 \(E_{i,t}\) 在统一图文特征空间里的相似度（用多模态检索模型 GME）：

\[ s_{i,t} = \mathcal{M}_{\text{retrieve}}(C_{i,t}, E_{i,t}) \]

第三步，双阈值过滤。只有当 bbox 置信度 \(c_{i,t} > \alpha\) 且 \(s_{i,t} > \beta\) 时才进入最终计算——把检测失败的帧剔除掉。

第四步，聚合：

\[ S_{\text{Nexus}} = \frac{1}{I \times T'} \sum_{i=0}^{I} \sum_{t=0}^{T'} \mathcal{M}_{\text{retrieve}}\left( C_{i,t}, R_{i} \right), \quad \text{其中 } c_{i,t} > \alpha \text{ 且 } s_{i,t} > \beta \]

这里 \(T'\) 是检测到目标的帧数而非总帧数。作者特意用 \(T'\) 作分母：如果只有一帧质量高而其余帧都很差，用总帧数平均会稀释出偏高的分数，按检出帧数归一能抑制这种"单帧刷分" #Yuan-et-al.-2025#。

身份度量口径的关键决定：NexusScore 刻意不使用任何人脸识别 embedding。作者在附录明确说"该指标不用于计算人脸相似度以提升鲁棒性，这也是为什么我们保留 FaceSim" #Yuan-et-al.-2025#。也就是说，在 OpenS2V-Eval 的 taxonomy 里，"通用主体一致性"（GME 图像空间 + 检测裁剪协议）与"人脸身份相似度"（FR 模型专用维度）被制度性地拆成两个维度。这与 VBench-2.0 把 DINO 的 subject consistency 与 ArcFace 的 human identity consistency 拆开的自我修正方向一致——两大 benchmark 各自独立地得出了"主体一致性 ≠ 人脸身份一致性"的结论，是 survey 口径区分论点的双证据。

3.2 FaceSim-Cur：人脸维度的口径选择

人脸相似度维度沿用 ConsisID 的协议：先用 insightface（ArcFace 生态的检测器）在视频帧和参考图中检测人脸区域，再在 CurricularFace 特征空间计算区域相似度，最后对全部有效分数取平均 #Yuan-et-al.-2025#。

FR 模型口径分歧：注意 OpenS2V-Eval 的 FaceSim 用的是 CurricularFace，而 VBench-2.0 的人脸维度用的是 ArcFace（RetinaFace 检测）。两个同期 benchmark 对"人脸身份维度该用哪个 FR 模型"没有统一口径，且本文没有对 FR 模型选择做消融。对 survey 而言，这说明即便社区已经接受"人脸身份需要专用 FR 维度"，FR 模型间的分数仍不可直接互比。

3.3 NaturalScore 与 GmeScore

NaturalScore：针对 copy-paste 问题的维度——评的是"生成的主体看起来自然吗、符合物理常识吗"。作者试过 AIGC 异常检测模型（准确率不佳）和开源多模态大模型（指令遵循差、幻觉重），最终用 GPT-4o 模拟人类评估员：按常识与物理定律设计五点量表，对均匀采样的 \(T\) 帧逐帧打分取平均 #Yuan-et-al.-2025#：

\[ S_{\text{Natural}} = \frac{1}{T} \sum_{t=1}^{T} \mathcal{M}_{\text{GPT}}(I_t) \]

实现细节：模型版本固定 gpt-4o-2024-11-20，长边 resize 到 512 像素，每个视频跑 3 次取平均 #Yuan-et-al.-2025#。

GmeScore：文本相关性。CLIP/BLIP 的特征空间有已知缺陷，且文本编码器 77 token 上限不适配 DiT 视频模型偏爱的长 prompt。GME 是在 Qwen2-VL 上微调的多模态检索模型，原生支持动态分辨率和变长文本，直接算文本-视频相似度 #Yuan-et-al.-2025#。

统一的评测协议：除 MotionScore 需要全帧外，其余指标（NexusScore、NaturalScore、GmeScore、FaceSim、AestheticScore）都按均匀采样 32 帧计算 #Yuan-et-al.-2025#。

3.4 人类偏好验证

新指标是否真的对齐人类感知？作者做了人工交叉验证：随机选 60 个生成视频，173 名参与者投票，采用二元配对问卷（两个模型生成的视频二选一），并对 NexusScore / NaturalScore / GmeScore 与人类偏好做相关性分析。结论是三个新指标均与人类感知对齐，且与 ArcFace、OpenCV、aesthetic 类既有指标可比 #Yuan-et-al.-2025#。人评质控相当严格：单 IP 限一次 + 登录、完成时间少于 5 分钟的提交剔除、播放顺序随机化、滑块验证防机器人、极端打分（最高分+最低分占比超 50%）的问卷剔除 #Yuan-et-al.-2025#。

与旧指标的直接对比（附录）：在用户偏好实验里，NexusScore 拿到约 69% 的偏好率，而 DINO-I 约 65%、CLIP-I 仅约 45%；GmeScore 约 70% 对 CLIP-T 约 62% #Yuan-et-al.-2025#。

图 3：(a) 新指标与既有指标的用户偏好对比——NexusScore 对 CLIP-I 的优势最明显；(b) 定性案例：CLIP-I 给 84.33% 高分的失败样本，NexusScore 只给 20.68%（来源：Yuan et al., 2025, Appendix Fig.14）。

四层批判，每层都有明确证据 #Yuan-et-al.-2025#：

  1. 任务错配：主流 benchmark（Make-a-Video-Eval、FETV、T2VScore、EvalCrafter、VBench、VBench++、ChronoMagic-Bench）全部为 T2V 设计，主体一致性维度整体缺失。
  2. 度量缺陷被继承：ConsisID-Bench 只评人脸一致性；Alchemist-Bench、VACE-Bench、A2 Bench 支持开域 S2V，但主体一致性指标直接继承 VBench——"直接计算未裁剪视频帧与参考图像的相似度，不可避免地引入背景噪声并降低精度"，而且 DINO/CLIP 特征空间本身已被证明不合理。
  3. 自然性维度集体缺失：没有任何前代 benchmark 评估"主体自然性"。后果是 copy-paste 型失败在现有分数里隐形——模型把参考图原样贴进视频，一致性分数很高，但产出不自然。
  4. 高分掩盖失败：即便生成的主体不自然或保真度低，现有 benchmark（作者点名 VACE、SkyReels-A2、VBench-2.0 的语境）仍然给出高分，阻碍领域进步。
与 survey 其他 benchmark 证据的连接：这层批判与 THEval（talking head 侧 FID/FVD/SyncNet 与人类偏好相关性全部不显著）和 FCB（GenAI 视频角色面部一致性专项协议）构成互证——2025-2026 年三个不同细分领域的 benchmark 论文不约而同地对"继承自上一代任务的度量"发难。OpenS2V-Nexus 的独特增量是把"一致性"与"自然性"拆成正交维度，直接把 copy-paste 暴露在分数上。
Part 5
OpenS2V-5M 数据集构成：百万级三元组 + 反捷径设计

5.1 数据漏斗

原始视频来自 Open-Sora Plan 爬取的 14,818,489 条网络视频。作者设计 100 个人类相关的动词/名词作为检索词，基于原始 caption 筛出 12,654,783 条人类相关视频；再用 Aesthetic Predictor、OpenCV 运动分、DOVER 技术分和 OCR（水印区域检测）过滤低质量数据，得到 5,437,544 条高质量 clip #Yuan-et-al.-2025#。

标注管线（沿 ConsisID 数据管线）：Qwen2.5-VL-7B 写主体中心的视频 caption → DeepSeek-V3 从 caption 提取环境与物体关键词 → 首帧 + 关键词输入 GroundingDino 检测主体 → bbox 输入 SAM2.1 生成去背景 mask → 得到主体-文本-视频三元组（regular data）。每条参考图再赋 aesthetic 分与 GmeScore，供使用者按需调质量阈值 #Yuan-et-al.-2025#。

5.2 Nexus Data：数据层的反捷径设计

论文对训练数据的关键洞察：现有 S2V 方法全部依赖 regular data——参考图直接从训练视频帧分割出来，这意味着参考图与训练帧同视角、可能不完整，模型会走捷径直接抄参考图而不是学习主体的内在知识，最终导致泛化差和 copy-paste #Yuan-et-al.-2025#。

Nexus Data 的两种配对 #Yuan-et-al.-2025#：

  • GPT-Frame Pairs：视频首帧 \(I_0\) 与主体关键词集合 \(K\) 输入 GPT-Image-1 生成完整主体图 \(I_{\text{gen}} = \mathcal{M}_{\text{GPT}}(I_0, K)\)，形成 \(\langle I_0, I_{\text{gen}} \rangle\) 配对。GPT-Image-1 能重建不完整主体并从多视角生成一致内容——参考图不再是训练帧的复制品，捷径被切断。资源受限下只取平均分最高的 top-10K 样本。
  • Cross-Frame Pairs：同一长视频切出的不同 clip 之间有天然时序/语义关联。用 GME 计算跨 clip 主体的相似度 \(S(C_{ij}, C_{kl}) = \text{sim}(\mathcal{M}_{\text{retrieval}}(C_{ij}), \mathcal{M}_{\text{retrieval}}(C_{kl}))\)，聚合同源 clip 形成配对。共识别 0.35M 个聚类中心，平均每个中心 10.13 个样本。

数据集有效性验证：以 Wan2.1 1.3B 权重初始化、用 ConsisID 方法微调（仅 MSE loss、不用 mask loss），随机取 300K 样本只训单人脸身份。加 Nexus Data 的版本（Ours‡）对比不加的版本（Ours†）全维度提升：Total +1.30%（52.97% vs 51.67%）、FaceSim +1.87%、Motion +1.94%、Natural +1.38% #Yuan-et-al.-2025#。作者强调模型未充分训练，实验仅为验证数据管线。

Part 6
18 个 S2V 模型的排名结论

评测覆盖 4 个闭源 + 14 个开源配置（VACE/Phantom 各算多档）。统一协议：官方实现、seed 固定 42、每个测试样本只生成一个视频（开源模型推理太慢——VACE-14B 在单张 A100 上生成一个 81×720×1280 视频要超过 50 分钟）；实验共消耗 40 张 A100 #Yuan-et-al.-2025#。

身份一致性视角的关键结论 #Yuan-et-al.-2025#：

  • 专用人域模型确实更能保身份：闭源里 Hailuo（人域专用）Total 60.20% 全场第一，超过开域通用的 Kling；开源里人域模型与开域模型互有胜负。
  • ConsisID 与 Concat-ID 的 FaceSim 相对不弱（43-50%），但 NaturalScore 显著偏低——作者将其归为显著的 copy-paste 问题；开源人域模型里 EchoVideo 的 NaturalScore 最高（69.22%）。
  • VideoMaker 悖论：FaceSim 76.45% 全场最高（断层领先第二名 64.65%），但 NaturalScore 47.08% 全场最低、GmeScore 45.28% 也几乎垫底。FR 分数与感知质量严重脱节——这给"只刷 CSIM/FaceSim 的模型未必是好模型"提供了最极端的实证案例，survey 度量批判章节可直接引用。
  • HunyuanCustom 主体保真高（FaceSim 62.25%）但"风格带人工痕迹、真实感不足"。

6.3 Single-Domain S2V 与定性发现

单主体任务上 VACE-14B 以 Total 58.00%、NexusScore 51.33%、FaceSim 64.65% 三项第一；Kling 的 NaturalScore 81.40% 仍最高 #Yuan-et-al.-2025#。定性分析暴露的现象学（对 survey 的时序漂移痛点有价值）#Yuan-et-al.-2025#：

  • 侧脸全灭：所有模型都无法准确生成人物侧脸轮廓；
  • 参考图越多，保真越低：多参考输入反而稀释身份信息；
  • 保真随时间衰减（Consistency Fade）：如戒指上镶嵌的钻石随视频推进逐渐消失，作者推测源自底座视频模型（Wan/HunyuanVideo/CogVideoX）；
  • 首帧模糊或直接复制：Kling 会把参考图直接复制为视频首帧，SkyReels-A2 首几帧模糊渐清晰，Phantom/ConsisID/Concat-ID 同样出现——疑似 VAE 作为控制信号的副作用；
  • 人类保真系统性弱于非人实体：作者归因部分在于人眼对脸更敏感，但主因是模型能力不足。

作者还给出面向社区的模型选型指南：内容创作者选 Kling（效果最好但推理贵，性价比之选 Pika/Vidu）；开发者基于 Phantom 或 VACE 微调；人中心视频（模特、口播）选 Hailuo（身份保持超过 Kling）；人中心开源开发选 HunyuanCustom 与 ConsisID 的预训练权重 #Yuan-et-al.-2025#。

Part 7
局限、开放问题与对 survey 的启示

7.1 论文自述局限

  • 人评对齐天花板约 75%：NexusScore 与 NaturalScore 与人类偏好的相关性只有约 75%，作者承认需要更好的自动指标——benchmark 作者自己承认新指标不够好，这个诚实的数字比指标本身更有引用价值 #Yuan-et-al.-2025#。
  • 版权掣肘：视频来自多个平台，只有符合 CC BY 4.0 或版权不受限的约 4M 条能公开（总数 5.4M）；含可识别人物，整个数据集限学术用途访问 #Yuan-et-al.-2025#。
  • 英文 prompt only：作者承认对汉服、功夫等非西方文化符号存在语义扭曲与误读风险 #Yuan-et-al.-2025#。

7.2 我们补充的批判（读论文时需要注意的协议弱点）

  • 单视频采样协议：每个测试样本只生成一个视频（seed=42），没有报告生成方差——扩散模型的采样随机性被完全忽略，模型间几个百分点的 Total 差距可能在噪声范围内。
  • NaturalScore 是 GPT-4o 黑盒：闭源 API 指标有成本、复现性（版本会退役）和可审计性问题；且 GPT 系模型同时被用于构造评测集（GPT-Image-1 合成 100 个合成样本的参考图）与打分，存在同源偏差风险。
  • 180 prompt 规模偏小：对比 VBench 的 946 prompt，统计功效有限。
  • 阈值不透明：NexusScore 的检测置信度阈值 α 与图文相似度阈值 β 的具体数值未披露。
  • 分辨率/帧率/时长不统一：各模型按各自官方设置生成（从 512×512×2s 到 1920×1080×5s），跨模型比较存在混杂因素——作者沿用 FETV/VBench 惯例，但引用排名时需注明。

7.3 留给身份一致性 survey 的开放问题

  1. 自动指标的人评对齐天花板：75% 是 GME+GPT-4o 组合的上限。突破要靠更好的 embedding、更好的协议，还是把检测裁剪式协议与 FR embedding 融合？
  2. 一致性与自然性的权衡：copy-paste 本质是数据捷径的产物，Nexus Data 证明可以在数据层面缓解（+1.30% Total），但代价是 GPT-Image-1 合成引入的分布偏移。训练目标层面如何显式权衡两个维度仍未解决。
  3. FR 模型口径分歧：OpenS2V 用 CurricularFace、VBench-2.0 用 ArcFace，无消融、无互比——FR 模型选择本身成为身份评测的未标准化变量。
  4. 时序衰减只有现象没有指标：Consistency Fade 被观察、被讨论，但 OpenS2V-Eval 的六维里没有任何量化时序漂移的维度（NexusScore 是全帧平均，漂移被平均稀释）。
  5. 侧脸与多参考衰减：两个失败模式都被定性指出，缺乏针对性的度量设计。

survey 引用速查

  • taxonomy：六维指标（NexusScore/NaturalScore/GmeScore + FaceSim-Cur/Aesthetic/Motion）+ 七类任务 + 三任务分组。
  • 身份口径：主体一致性（GME 图像空间）与人脸身份（CurricularFace）制度性分离；NexusScore 刻意不用 FR embedding。
  • 批判：VBench 系未裁剪帧相似度引入背景噪声 + DINO/CLIP 空间不合理 + naturalness 缺失 + 高分掩盖失败。
  • 排名：Open-domain Kling 54.46% 第一；Human-domain Hailuo 60.20% 第一；VideoMaker FaceSim 76.45% 最高但 Natural 47.08% 最低。
  • 数据集：5.4M clip（14.8M→12.65M→5.44M 漏斗），0.35M Nexus Data（GPT-Frame top-10K + Cross-Frame 0.35M 中心）。
  • 局限：~75% 人评相关性天花板；单视频协议；GPT-4o 黑盒；英文 only。
