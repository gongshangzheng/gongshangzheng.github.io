# Phase 2 · 结构规划

**目标**：把原书章节映射到博客文章。决定单篇 vs 系列、拆篇维度、Hub 设计，输出结构图供用户确认。

## 2.1 拆篇决策树

```
全书章节数？
├─ 1-3 章 / 总篇幅 < 4000 字 → 单篇（extract 模式或 full 单篇）
├─ 4-12 章 → 系列：一章一篇 + Hub
└─ 13+ 章或章内庞杂 → 系列按"类型/主题"归并，每篇覆盖一个主题群
```

book-to-skill 的"按章按需加载"哲学在此体现：每篇对应原书一个可独立阅读的单元，不强行合并也不强行拆细。

## 2.2 常见拆篇模式

| 书的类型 | 拆篇维度 | 示例 |
|---------|---------|------|
| 教程/技术书 | 一章一篇 | 《Think Python》每章一篇 |
| 人物目录/辞典 | 一类一篇（人物按类型归并） | 《美国职业罪犯》每种犯罪类型一篇 |
| 历史叙事 | 一时段/事件一篇 | 一朝代一篇 |
| 论文集 | 一篇论文一篇 | 论文集每篇一篇 |
| 手册/参考 | 按主题群归并 | API 参考按模块归并 |

## 2.3 含目录式条目的书（人物/辞典类）

若书有"手法/总论" + "条目目录"两层结构（如《美国职业罪犯》：Part I Methods 论文 + Part II ~200 条人物目录）：

- 每个类型/章节 = 一篇，**手法讲解 + 该类型条目目录**合并进同一篇
- 条目按原书类型标签归并到对应手法篇，不单独成篇
- 条目用统一格式转写（见 `references/entry-format.md`）
- 补充章节（附录、专题）单独成篇

## 2.4 Hub 页设计

系列 ≥ 2 篇 → 建 Hub。Hub 内容：
1. 引论：书的基本信息（书名、作者、年代、来源）+ 为什么读 + 阅读指南
2. 知识地图：用 `.code-tabs.hub-tabs` 三标签（列表 / 卡片 / 图谱）
3. 章节卡片：`.period-card` + `.period-grid`，每张卡片 = 一篇的入口（编号、标题、摘要、该篇覆盖的人/主题数）
4. `{{< sortable-list "taxonomy" >}}` 全文章清单
5. 阅读路径建议
6. 原书信息框（`.info-box`）

Hub 必须用 `node capture.js <slug>-hub --hub` 创建（hub 模板）。

## 2.5 标题与编号

- **标题前缀**：`<书简称>系列（N）：<章节主题>`，如 `美国职业罪犯系列（三）：伪造犯`
- **sub_id**：Hub `sub_id: 0`；系列文章同级编号步长 10（10, 20, 30...）
- 分配前运行：`~/.venv/bin/python3 ~/gongshangzheng.github.io/scripts/check-sub-id.py --category <分类关键词>`
- 所有文章 `aliases` 分类路径一致：`categories/读书笔记/<书名>`

## 2.6 输出结构图

向用户呈现：

```
书名：《XXX》（作者，年代）
分类：categories/读书笔记/<书名>
模式：full / extract
├─ Hub: <slug>-hub.html（sub_id: 0）
├─ 篇1: <slug>-ch01.html（sub_id: 10）— <主题>
├─ 篇2: <slug>-ch02.html（sub_id: 20）— <主题>
...
└─ 篇N: <slug>-chNN.html（sub_id: N0）— <主题>
每篇预估字数：XXXX 字
```

用户确认后进入 Phase 3。

## Gate 条件

进入 Phase 3 前必须满足：

- [ ] 拆篇方案已定（单篇 or 系列 + 拆篇维度）
- [ ] Hub 设计已定（≥ 2 篇时）
- [ ] 标题前缀 + sub_id 区间已分配
- [ ] 分类路径已选（复用 or 新建）
- [ ] 结构图已呈现给用户并获确认
- [ ] 已创建 todo 并将 Phase 3 设为下一步
