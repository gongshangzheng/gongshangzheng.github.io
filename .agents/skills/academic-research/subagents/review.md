# Review Subagent

## 任务

审查学术调研报告的完整性和质量。

## 输入

- `研究领域`: 当前调研主题
- `HTML 报告`: `~/gongshangzheng.github.io/src/pages/<slug>.html`
- `Survey spine`: `~/Org/roam/note/<topic>/survey-spine.md` 或 `phase3-survey-reorganization.org`
- `Paper/reference packets`: `~/gongshangzheng.github.io/raw/<slug>/synthesis.md`、`survey-ledger`、原始 source/HTML/PDF 指针
- `原始素材`: 原始论文、原始 survey 全文、官方项目页、仓库和数据集文档

## 检查清单

### 1. 覆盖完整性
- [ ] Phase 0 领域地图中的所有热点子方向都有覆盖
- [ ] Phase 1 目标论文列表中的所有论文都被引用
- [ ] 每篇 `core-survey` 已发布为可构建、可公开访问的 HTML 参考页；若未发布，有用户明确豁免记录
- [ ] 每篇 `must-read-paper` 已完成 read-article 深读并发布为可构建论文精读 HTML；若未发布，有用户明确豁免记录
- [ ] 每篇 `must-read-paper` / `route-representative` 在 survey 正文中都有简要论述，而不是只出现在表格或参考文献里
- [ ] 每篇 `must-read-paper` 至少有 1 张核心图片进入最终 survey；若没有，说明不可取得原因和替代图方案
- [ ] Survey 的核心结论已被整合
- [ ] Landmark 的历史地位已被说明
- [ ] Recent 的新颖性已被讨论

### 2. Survey 结构质量
- [ ] 开头 20% 篇幅由浅入深说明领域建模问题、输入/输出、约束、优化目标、常见误解和最小术语表；没有直接进入论文罗列
- [ ] `任务 Taxonomy` 与 `技术路线 Taxonomy` 分开，且每类都有边界、不适用场景、代表论文和评测重点
- [ ] 方法矩阵覆盖表示、驱动信号、训练数据、输出形式、实时性、可控性、评测指标和工程可得性
- [ ] 时间线不是按年份列论文，而是解释阶段共识、瓶颈和转折
- [ ] 章节之间有“问题 → 建模选择 → 方法演进 → 对比证据 → 局限”的递进关系
- [ ] 文章回答了一个明确的 survey 主问题，而不是多篇论文摘要拼接

### 3. 信息准确性
- [ ] 抽查 5 个具体数值是否与原始论文一致
- [ ] 无编造的方法/数据/结论
- [ ] 论文之间的对比基于实际数据
- [ ] 最终 HTML 正文没有 raw 路径、`file_path:start_line-end_line`、ledger 路径、figure pointer 或“见原文指针”式占位；所有中间指针都已转写为读者可理解的解释、论证说明、引用和图片 caption。

### 4. 深度要求
- [ ] 每个 taxonomy 节点至少引用 2 篇论文或 1 篇核心 survey + 1 篇代表论文
- [ ] 方法对比表有具体数值或明确说明原文未披露，不能只写“更好/更快/更自然”
- [ ] 开放问题至少 5 个，每个说明为什么仍未解决、受哪些论文或数据支持
- [ ] 包含具体超参数、数据集、训练/推理成本、延迟/FPS 或评测设置信息；未披露项也要显式说明
- [ ] 核心 survey 的 taxonomy、数据集、指标、局限已被吸收进主文，而不是只在参考页或脚注中出现
- [ ] 重要论文论述段落至少说明：问题、路线、相对前后工作的变化、关键证据、局限和论文精读链接

### 5. 格式规范
- [ ] 公式使用 `\(...\)` / `\[...\]`
- [ ] 表格使用 org-mode 格式
- [ ] 无空段落
- [ ] HTML 正文字数和各章节字数满足 Phase 4 最低要求，并附统计结果
- [ ] HTML 标题存在清晰层级，至少包含主章节、二级小节和必要的三级说明标题；不是全篇同级标题
- [ ] HTML 中至少包含 3 张关键图片，且覆盖 `must-read-paper` 的核心图片要求
- [ ] 所有图片引用使用实际存在的文件

## P0 拦截条件

任一项成立时，最终文章不得发布，必须退回 Phase 3/4 重写：

- 开头没有讲清领域核心问题、输入/输出和建模约束
- 没有任务 taxonomy 或技术路线 taxonomy
- taxonomy 只是论文列表，没有边界、不适用场景和代表任务
- 文章主体按论文逐篇介绍，缺少跨论文比较和方法矩阵
- 没有开放问题，或开放问题只是泛泛而谈
- 关键判断无法追溯到原始论文、核心 survey 全文、survey ledger 或官方材料
- 最终 HTML 正文出现 raw 路径、`file_path:start_line-end_line`、ledger 路径、figure pointer 或“见原文指针”式占位，而没有转写成真正的解释和引用说明
- 任一 `core-survey` 未发布公开 HTML 参考页，且没有用户明确豁免
- 任一 `must-read-paper` 未 read-article、未发布论文精读 HTML，且没有用户明确豁免
- 任一 `must-read-paper` 或关键路线代表论文只在表格/参考文献中出现，没有正文简要论述
- 任一 `must-read-paper` 没有核心图片进入最终 survey，且没有不可取得说明和替代图
- HTML 正文字数或关键章节字数低于 Phase 4 最低要求
- 最终 HTML 标题全篇同级、缺少 h2/h3/h4 或等价层级
- 读完后不能回答“这个领域到底在解决什么问题、有哪些路线、各自适合什么场景”

## 缺口分析

列出所有 ❌ 和 ⚠️ 项，对于每个缺口：
1. 说明缺失内容
2. 指出应从哪篇论文、survey ledger 或原始来源的哪部分补充
3. 提供具体补充内容（HTML 或 Markdown 片段）

## 交叉一致性

检查不同 section 中对同一论文/方法的描述是否一致。如有矛盾，指出并给出正确版本。

## 约束

- 不限制输出长度
- 每个缺口必须提供具体补充内容
- 抽查的数值必须实际从原文核对
- 直接编辑笔记和 HTML 文件补充缺口
