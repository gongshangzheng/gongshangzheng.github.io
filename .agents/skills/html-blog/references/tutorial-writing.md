# 入门与实操教程写作

适用于软件、开发工具、Agent 等使用教程。依据 `openspec/changes/agent-tutorial/` 的迭代和最终 `src/pages/agent-tutorial.html` 提炼；保留可迁移的写作方法，产品名单、套餐价格、视频和六章结构只属于该案例。

## 读者路径与文章范围

先在 design 中写清读者已经知道什么、读完能完成什么，以及本文补充什么。作者与读者分开：用户是文章作者，正文中的“你”是正在学习的读者。“由你提供的视频”等协作对话不进入正文。

按读者实际使用的依赖关系安排章节。一种适合工具入门的路径是：产品与入口 → 服务和费用 → 必要背景 → 日常配置与方法 → 任务执行 → 安全与结果复核。顺序随主题调整，不固定章节数。读者需要先完成任务时，原理部分可标为选读，并给出明确跳转；后续必读部分应能独立理解。

用户要求一篇完整教程时，分章写作和审核仍整合在同一 slug 中；不因分阶段交付而加“第一篇”、另建系列或 Hub。已有页面直接调整，不重新创建同主题文章。确认的视频已经承担基础演示时，正文补充使用技巧，不重复整套视频操作。

## 标题与讲解节奏

在 design 中先列章节及三级、四级标题，再写正文。章节标题对应阅读阶段；`h3.section-title` 只承载主要主题；步骤、例子、加载方式、比较和注意事项放在 `h4.ch-section` 下。以主要概念组织三级标题，例如“AGENTS.md”和“Skill”，不要把每个细节都提升成目录项。一个章有几个主要主题由内容决定，不为了缩编强行合并独立主题。

可见标题使用能独立说明内容的短词组。删除“先认识”“先来看看”“想先看个演示”等铺垫词和无信息问句。“认识模型服务”可改为“模型服务”，“为什么需要规划”可改为“规划与执行”。完成后单独通读页面目录，核对信息量、层级和 design 的一致性。

段落采用问题或场景 → 解释 → 示例或做法的推进方式，不必每段都用问句开头。先用熟悉的词说明作用，再引出术语；同一任务场景可以贯穿相关概念。表格压缩比较，清单呈现步骤，普通段落承担解释和过渡。避免每节机械增加总结、提示框或免责声明。

写作策略、素材筛选过程和编辑备注留在规划文件。例如“本文仅提供延伸观看内容，不据标题转述教程”是内部核验策略；正文可以直接写观看范围和时间点。只有影响读者选择或操作的信息，如版本、适用平台、费用和权限边界，才需要说明。

## 概念与事实核验

先查官方文档，再写机制。把产品、模型、API 服务、付费权益和运行框架分清；同一厂商的产品不能因品牌相同就视为同一服务。推荐说明交互门槛、任务适配和限制，不把示例工具写成绝对排名，也不沿用已过时的“其他产品只有终端”等描述。

解释机制时交代谁发现、谁加载、谁执行、输入是什么、结果到哪里。类比帮助理解后，接上实际流程；不要把近似理解写成产品事实。Agent 类教程尤其核对以下区别：

- 模型可生成文字答复或结构化工具请求；Harness 组织运行流程并调度工具，不是每次输出都调用工具。
- 工具结果回到上下文，模型据此继续处理；文件、网络和命令权限由实际运行机制控制，不能只靠提示词限制。
- 指令文件的发现范围与内容加载是两件事。说明 AGENTS.md 时，按具体产品核对目录链、优先级、全文合并和长度限制，不能误写成模型逐条筛选规则。
- Skill 的发现描述、按需读取的指令、参考资料和脚本有不同用途，不笼统宣称所有内容在启动时完整进入上下文。

这些机制都可能随产品和版本变化，数值上限、路径和默认行为回到当前官方文档核对，不能把本案例中的 Codex 规则推广到全部 Agent。

费用比较统一标明币种、地区、计费单位、月付或年付总额、额度、服务权益与核查日期。按低频、日常和高用量讨论，不断言 API 天然更贵或套餐必然更便宜；“规划用强模型、执行用经济模型”也只是按任务选择的策略，不保证省 Token 或提高质量。

推荐现成资源时给发现入口和少量任务相关的实例，并说明实际交付物。例如网页演示与可编辑 PowerPoint 文件不能混为一种输出。涉及第三方脚本或插件时，说明原始来源、指令、权限及密钥处理的检查方法；目录热度或精选标记不等于安全保证。

## 视频与配图

视频按用途放置：完整入门演示可用站点支持的播放器组件；局部配置演示可给时间戳直达链接。标题不能作为内容证据；核对页面与相关片段，并在参考来源记录作者、原始 URL 和核查日期。渲染后确认播放器真正出现、时间戳链接指向正确位置。

每张图解决一个具体阅读问题：截图展示产品入口或真实价格，关系图解释职责和上下文，流程图解释工具循环或任务规划。紧邻相关文字放置，避免装饰图和重复操作截图。

网页截图先等内容稳定加载，再回到顶端并确认位置。该案例按用户要求进入页面后至少等 4 秒；等待时长不是完整加载的证明，仍需检查字体、图片、价格和弹窗。拼图统一尺度、保留辨认产品和关键内容所需区域，裁掉大块无效留白，保证价格和标签可读。记录来源与日期；替换后先确认旧图不再被引用，再删除旧文件。图片格式与组件仍遵循 blog-syntax 和 blog-images。

流程图与正文共享同一机制：分清文字回答和工具请求、上下文内容和实际权限、按需加载和完整文件加载。图注解释图的关键关系，不额外堆叠写作策略。

## 规划同步与验收

用户修订结构或机制后，把决定落到 design 的章节骨架、必备元素、标题层级和配图计划；涉及范围或验收变化时同步 proposal 与 specs，再更新 tasks。开始执行前检查 tasks 是否覆盖最新 design，不能只修改 design 后沿用旧任务表。

已经完成的旧版任务保留历史完成状态；新的重排、补写、概念纠正和素材替换增加本轮任务，并附对应复核项。任务按可执行、可验证的结果拆分，不以“越细越好”为标准。

正文完成后对照 design 检查章节、标题、概念机制、视频范围、图片和安全复核内容。教程验收关注读者能否完成目标、步骤是否可执行、结果如何判断；不用论文的公式数、超参数数和消融实验作为通用质量底线。涉及写文件、联网或付费服务的教程，给出具体的权限、敏感信息、结果检查和回退方法。

使用现有 HTML lint 与构建流程检查页面，并验证新增媒体和链接的实际呈现；站点逻辑有变动时再运行相关测试。已有测试结果只覆盖当时版本，后续改动按影响重新验证。发布、草稿处置和其他外部操作按用户已授权范围执行。
