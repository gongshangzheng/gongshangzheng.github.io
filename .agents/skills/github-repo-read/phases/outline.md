# Phase 7: 综合分析与写作提纲

**目标**：将前几个阶段的发现综合为结构化分析，形成写作提纲。

## 7.1 综合分析框架

形成以下结构：

| 维度 | 内容 |
|------|------|
| 一句话定位 | 这个项目是什么，适合谁 |
| 为什么值得读 | 工程/研究/产品角度的价值 |
| 仓库地图 | 目录、入口、核心模块 |
| 架构可视化 | 系统架构图 / 模块依赖图（Mermaid），有 DB 时加 ERD |
| 主调用链 | 从用户 API 到核心实现（推荐 Mermaid 时序图） |
| 核心算法 | 逻辑复杂处用伪代码提炼；涉及数学/几何/坐标变换时可选 JSXGraph 交互演示 |
| 关键设计 | 3-6 个最值得讲的设计 |
| 代码证据 | 每个设计对应文件路径/函数 |
| 图片证据 | GitHub/用户图/官方图，说明其论证作用 |
| 工程评价 | 优点、局限、复现风险 |
| 可迁移经验 | 哪些模式可用于别的项目 |

## 7.2 写作提纲

### 模板

```markdown
# [项目名]：[一句话定位]

## 背景与动机
- 要解决什么问题
- 现有方案的不足

## 项目概览
- 一句话定位
- 核心卖点
- 技术栈

## 架构与设计
- 仓库地图（目录结构图/表）
- **系统架构图 / 模块依赖图（Mermaid `graph`，强烈推荐）**
- **主调用链时序图（Mermaid `sequenceDiagram`，强烈推荐）**
- 数据模型 ERD（Mermaid `erDiagram`，有数据库时）
- 核心模块关系

## 关键实现
### 设计点 1：[名称]
- 问题/动机
- 解决方案
- 代码证据（文件路径 + 代码片段，≤40 行）
- **核心算法伪代码（逻辑复杂时；推荐与流程图同 `code-tabs`）**
- 图片证据（如有）

### 设计点 2：[名称]
...

## 工程评价
- 优点
- 局限
- 复现风险

## 可迁移经验
- 哪些模式可以借鉴

## 参考
- 项目链接
- 论文链接（如有）
- 相关资源
```

## 7.3 与用户确认提纲（可选）

如果是 `blog` 模式或用户要求深度分析，建议将提纲发给用户确认：

- 章节顺序是否合理
- 重点设计点是否覆盖用户关心的内容
- 是否需要补充或删减

## Gate 条件

进入 Phase 8 前必须满足：

1. **综合分析框架**各维度全部填写完成（含架构可视化、主调用链、核心算法）
2. **写作提纲**已形成，结构完整，已规划好架构图 / 时序图 / 伪代码的落点
3. **用户确认**（如需要）已获得
4. **todo 状态**：Phase 7 标记为 `completed`，Phase 8 标记为 `in_progress`

不满足？补齐后重新检查 Gate。
