# 草稿事实性核查 (factcheck)

## 任务

对 `drafts/<slug>.md` 草稿中的**事实性陈述**进行核查——验证定义、数值、归属、时间线、引用链接是否
准确，标记错误 / 不精确 / 未验证的陈述。对象是用户 brainstorming 草稿（学习笔记式），不是已发布的
论文解读，所以要区分"事实陈述"与"个人笔记/疑问"。

## 参考

read-article skill 的 `subagents/review-fidelity.md`——本流程借鉴其 P0/P1/P2 分级与"回原文核查"
精神，但"原文"在这里换成**权威来源**（arXiv 论文、官方文档、教科书、Wikipedia）+ 草稿正文末尾
"参考资料"节。

## 输入

- 草稿：`~/gongshangzheng.github.io/drafts/<slug>.md`
- 草稿参考资料：草稿正文末尾"参考资料"节
- 候选事实陈述（可选起点）：`scripts/draft.py factcheck <slug>` 的启发式提取结果
- 参考模板：`~/.claude/skills/read-article/subagents/review-fidelity.md`

## 第一步：区分陈述类型

逐句过草稿正文，把每条陈述分到三类之一：

1. **事实性陈述（需核查）**
   - 定义："X 是 Y"、"X 叫做 Y"、"X 指的是 Y"
   - 数值/百分比/年份
   - 归属："X 提出了 Y"、"X 团队的工作"
   - 时间线/演进："A → B → C"
   - 引用链接、引用论文/方法名
2. **个人笔记/观点/疑问（跳过，不核查）**
   - 用户自己的体会、TODO 疑问（"- [ ]"）、主观判断、"我的理解是…"
   - 这些不是事实陈述，不核查对错，只在报告中标注"个人笔记，跳过"
3. **模糊/笼统表述（标注，不强核查）**
   - "一般来说"、"可能"、"大概"——这些本身已 hedged，不必逐条查，但若含具体子陈述则核查子陈述

## 第二步：核查方法

对每条事实性陈述：

1. 用 `web_search`（或 google-research MCP）查权威来源：arXiv 论文、官方文档、教科书、Wikipedia。
2. 核对陈述与来源是否一致。
3. 分级：
   - **P0**：明确错误（与来源矛盾），必须改。例：把 RMSNorm 说成"减均值"。
   - **P1**：不精确 / 过度泛化 / 缺限定条件，应改。例："Transformer 都用 LayerNorm"（忽略 RMSNorm 变体）。
   - **P2**：可改进（表述更准确 / 补来源）。
   - **✅ 正确**：与来源一致。
4. 找不到权威来源的标 **"未核实"**——不要臆断对错，明确说"未找到公开来源核实"。

## 第三步：报告

按 **P0 → P1 → P2 → 未核实 → ✅正确（仅计数）** 顺序输出。每条：

```
### [级别] 原文陈述
- 草稿原句：「…」
- 核查结果：错误 / 不精确 / 未核实 / 正确
- 依据：来源 URL + 一句话
- 修复建议：…（若需改）
```

最后给一句**总结**：草稿事实性整体可信度（高/中/低）+ 主要风险点。

## 输出位置

默认在对话里直接报告（用户看完即用，不污染 drafts/）。
若用户要存档，写入 `drafts/<slug>.factcheck.md`（git 可跟踪，`draft.py list` 只扫顶层 *.md，
不会把 .factcheck.md 当草稿；但为避免混淆，优先在对话报告）。

## 强制要求

- 只核查，**不修改草稿**（除非用户明确说改）。
- 区分事实陈述 vs 个人笔记——不强核查用户的主观体会。
- 找不到来源一律标"未核实"，不臆断。
- 每条 P0/P1 必须附来源 URL。
- 网络/工具受限时按 read-article review-fidelity 的做法：书目事实以草稿参考资料为准，
  核心贡献/数值综合 search 结果 + 草稿原文，区分信息来源。
