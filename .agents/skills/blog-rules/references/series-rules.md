# 系列文章规则

> 本文档是博客系列文章**内容组织**的唯一事实来源。
> `sub_id` 编号与 taxonomy 索引替换规则见 `blog-aliases` skill。

---

## sub_id 与 taxonomy

→ 规则见 `blog-aliases` skill（`~/gongshangzheng.github.io/.agents/skills/blog-aliases/SKILL.md` §5）
→ 分布数据见 `blog-categories/references/subcategory-organization.md`（分配 sub_id 时按需读取）

**快速参考**（完整规则以 blog-aliases 为准）：
- Hub 固定 `sub_id: 0`
- 所有步长统一为 **10**，无例外
- 系列章节 `10–999`，论文精读 `1000–1999`，工程 `2000–2999`
- 新内容类型开新谱段：`3000`, `4000`, `5000`...（1000 的整数倍入口）
- 分配前**必须检查**同 subcategory 已有 sub_id（见 `blog-categories/references/subcategory-organization.md` 已发布文章清单）

## Hub 页内容结构（强制）

Hub/总览篇承担目录、导读和路线图功能，必须包含：

1. **系列定位**：说明系列主题、目标读者、阅读顺序和每篇边界
2. **全局术语地图**：帮助读者先建立心智模型
3. **章节目录**（`chapter-list` 布局）：
   ```html
   <ul class="chapter-list">
     <li><span class="chapter-num">01</span>
         <span class="chapter-title"><a href="article1.html">标题</a></span>
         <span class="chapter-status done">✓ 已完成</span></li>
   </ul>
   ```
4. **自动文章列表**：`{{< sortable-list "categories/分类/子分类" >}}`
5. **关系图**：`{{< post-graph "categories/分类/子分类" >}}`
6. **阅读路径**：推荐不同背景读者的阅读顺序

### 新增文章时同步更新 Hub

新增系列文章时必须同步更新：
- `chapter-list` 中的条目
- 阅读路径
- 路线导读
- 显示编号

## 标题前缀与编号（强制）

`sub_id` 只解决排序，标题前缀解决读者识别。同一类文章使用统一前缀和连续编号：

| 类型 | 标题格式 |
|------|---------|
| 系列总览 | `<子分类>系列总览：...` |
| 系列章节 | `<子分类>系列（一）：...` |
| 论文精读 | `<子分类>论文精读（序号）：论文名，副标题` |
| 工程解读 | `<子分类>工程解读（一）：...` |

**禁止**：同一 subcategory 下标题有的叫论文名、有的叫技术名、有的叫"深度解读"而无法看出所属专题。

---

## 跨篇连续性

系列文章不是若干篇松散短文，应像一本小书：

1. **每篇开头**：说明"上一篇解决了什么，本篇继续解决什么"
2. **每篇结尾**：给出本篇小结和下一篇入口
3. **术语一致**：核心术语、缩写、变量名和图例命名在全系列保持一致

---

## 统一 frontmatter

所有系列文章必须共享：

```yaml
categories: [同一个]
subcategory: "同一个"
hub: <hub-slug>       # 指向 Hub 页
sub_id: <唯一编号>     # 按 blog-aliases 分段规则
```

---

## 字数与密度要求

| 页面类型 | 最低正文量 | 适用说明 |
|---------|------------|----------|
| Hub / 总览页 | ≥ 1500 字 | 系列定位、阅读路径、术语地图、目录 |
| 普通专题篇 | ≥ 3000 字 | 单一概念链路、轻量教程 |
| 深度专题篇 | ≥ 4000 字 | 协议、源码、工程架构、系统综述 |
| 课程/教材式专题 | ≥ 3000 字 | 概念、推导、例子和图示完整 |

用户明确要求"深入""硬核""源码级"时，不得低于 4000 字/篇。

## 质量检查清单

发布前必须逐项确认：

- [ ] 所有文章在同一 `subcategory` 下
- [ ] 所有文章有唯一 `sub_id`（按 blog-aliases 分段规则）
- [ ] 每篇有开篇导读和术语闸门
- [ ] 核心术语首次出现时已解释
- [ ] 每篇达到对应字数下限
- [ ] Hub 目录、前后篇导航和 taxonomy index 关系一致
- [ ] `node build.js` 通过，无 lint 错误

---

## 系列拆分判断

满足任一条件即应拆为系列：

- 用户明确要求"多篇文章""系列""Hub/目录页"
- 主题跨度大，单篇会承担多重任务（综述+教程+工程+选型）
- 文章间存在天然阅读顺序（基础→协议→架构→工程→应用）
- 论文池超过 8 篇

拆分后采用"写书"结构：总览篇=序章，专题篇=章节，最终篇=结语。
