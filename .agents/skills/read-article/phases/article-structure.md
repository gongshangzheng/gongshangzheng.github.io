# Phase 4 · 文章架构规划

在 Phase 3 综合整理完成后、Phase 5 HTML 写作开始之前执行此阶段。

## 目的

Phase 2 的四个 subagent 按维度拆开分析（背景/引用/宝藏/方法论），Phase 3 做了综合整理。但综合整理 ≠ 知道文章怎么组织。同一批素材，用不同结构写出来读感完全不同。

此阶段的任务是：在动笔之前，先规划好文章的"骨架"，确保：

- 核心方法有足够的展开篇幅
- 公式和直觉交替出现，不是堆砌
- 每章有明确的叙事功能（铺垫/推进/转折/收束）
- 配图有计划地分布在各章节
- 字数分配合理，总量达标

## 核心原则

**论文深度解读以教学式叙事为目标，不是逐章节翻译论文。**

读者要的是"读完之后我能给别人讲清楚这篇论文在干什么"，不是"论文的中文翻译版"。

## 工作流程

### 第一步：分析全部素材

收集 Phase 3 的 synthesis.md + 4 份 subagent 分析结果，通读一遍，列出：

- **核心贡献**：论文最想让人记住的 1-2 个点
- **关键公式**：必须出现在文章中的核心数学表达（3-5 个）
- **实验亮点**：最有说服力的定量结果（带具体数值）
- **失败/局限**：作者承认的不足，消融实验的关键发现
- **配图资源**：已收集到哪些高质量图片（论文原图、架构图、结果图）
- **Insight**：为什么这个方法 work？突破点在哪？

### 第二步：设计文章结构

根据论文特征，选择最适合的结构。常见选项：

**A. 方法驱动型**（Method-Driven）
适用：论文提出一个完整的新方法/架构
结构：问题定义 → Insight → 方法详解 → 训练 → 实验 → 总结
```
引言（为什么值得关注）→ 问题分析（现有方法为什么不行）→ 核心思想（Insight）→ 方法详解（pipeline 全链路）→ 训练细节 → 实验分析 → 局限与启发
```
优点：逻辑清晰，从问题到解法的完整闭环
适合：大多数提出新方法的论文

**B. 对比驱动型**（Comparison-Driven）
适用：论文的核心贡献是改进已有方法，或在不同方法间建立桥梁
结构：已有方法分析 → 本文方法 → 逐点对比 → 实验验证
```
引言 → 前置方法详解（A vs B）→ 本文方法（如何统一/改进）→ 对比表格 → 实验分析 → 启发
```
优点：对比性强，读者能清楚看到差异
适合：改进型、桥接型、统一型论文

**C. 问题驱动型**（Problem-Driven）
适用：论文解决的是一个经典问题或开创一个新问题
结构：问题定义 → 已有解法 → 本文解法 → 为什么更好
```
问题是什么 → 问题为什么难 → 已有解法的局限 → 本文解法 → 实验验证 → 讨论与展望
```
优点：问题导向，读者始终知道"我们在解决什么"
适合：理论型、分析型、benchmark 论文

**D. 技术解析型**（Technical Deep-Dive）
适用：论文有大量工程/实现细节，适合做源码级解读
结构：整体架构 → 逐模块深入 → 训练技巧 → 复现要点
优点：技术密度高，适合有代码仓库的论文
适合：框架型、系统型论文

### 第三步：详细大纲

选定结构后，列出详细大纲：

```
结构方案：[A/B/C/D]
章节目录：
  Section 1 · [标题] — [本章核心内容，2-3 句话]
    配图计划：[哪张图，来源]
    预估字数：[≥N 字]
  Section 2 · [标题] — ...
    ...
  Section N · [标题] — ...

总预估字数：常规论文 ≥ 2500 字；复杂系统/综述论文 ≥ 3500 字
配图总数：≥ 3 张（其中代码绘制 ≥ 1 张）
```

### 第四步：推荐 + 用户确认

给出推荐方案。如果用户没有明确偏好，直接按推荐执行，不必等待确认。

用户确认信号：用户回复"可以"、"执行"或直接给修改意见。

## 字数分配模板

| 部分 | 占比 | 最低字数 |
|------|------|---------|
| 引言 + 背景 | 10-15% | 250 字 |
| 问题分析 + Insight | 10-15% | 250 字 |
| 方法核心 | 35-40% | 900 字 |
| 训练 + 实验 | 20-25% | 450 字 |
| 讨论 + 总结 | 10% | 250 字 |
| **总计** | 100% | **常规论文 ≥ 2500 字；复杂系统/综述论文 ≥ 3500 字** |

## 配图规划模板

| 位置 | 图片类型 | 来源 | 格式 |
|------|---------|------|------|
| 方法核心章节 | 架构图 | 论文 Fig.2 | .photo |
| 方法核心章节 | pipeline 流程图 | 代码绘制 | {{< mermaid >}} |
| 实验章节 | 结果对比图 | 论文 Fig.5 | .photo |
| ... | ... | ... | ... |

## 检查清单

开始写 HTML 之前，确认以下问题都有明确答案：

- [ ] 每个章节有明确的叙事功能（不是"这一段翻译了论文的 X 节"）
- [ ] 核心公式分布在方法章节，不是堆在一个 block
- [ ] 配图在各章节均匀分布（不是全堆在方法章节）
- [ ] 字数分配满足总量：常规论文 ≥ 2500 字；复杂系统/综述论文 ≥ 3500 字
- [ ] 至少 3 张图片，至少 1 张代码绘制

## 输出

本阶段输出：
1. 素材分析摘要（核心贡献、关键公式、配图资源）
2. 选定结构方案 + 详细大纲（含字数分配和配图计划）
3. 用户确认信号（或默认执行确认）

拿到确认后，才进入 Phase 5（HTML 写作）。
