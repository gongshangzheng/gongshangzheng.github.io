# 统一审校清单（Phase 7）

> read-article Phase 7 的唯一检查清单。三个维度**由主 agent 连续执行**；只有某一维度仍有独立且
> 耗时的核查需求时，才按需委派对应的 Review lane（模板在 `../subagents/review-*.md`）。

**输入**：

- HTML：`~/gongshangzheng.github.io/src/pages/<slug>.html`
- 原文：`~/gongshangzheng.github.io/raw/<slug>/sources/<slug>.md`
- 索引：`~/gongshangzheng.github.io/raw/<slug>/synthesis.md`
- 已确认大纲：`openspec/changes/<change-name>/design.md`

**输出**：问题清单（P0 阻断 / P1 强烈建议 / P2 可选）+ 修复记录。**P0 修复后才能进入 Phase 8。**

---

## 维度 A · 保真度（必须回原文核查）

### A1 核心贡献

- [ ] 论文试图解决的核心问题是否被正确描述
- [ ] 论文声称的"首次"或"超越 SOTA"是否有原文支撑
- [ ] 方法的直观原理（insight）是否准确反映作者设计意图

### A2 数值与公式

- [ ] 抽查 5 个具体数值（指标、参数量、数据集规模），与原文核对
- [ ] 抽查 3 个数学公式的符号定义、下标、运算符与原文一致
- [ ] 损失函数形式正确（特别是各项系数和权重）

### A3 实验设置

- [ ] 数据集名称、规模、划分与原文一致
- [ ] Baseline 方法列表包含原文所有对比方法
- [ ] 评估指标上下标正确
- [ ] 实验配置表（Part 6）六项与原文一致。**推理硬件为重点核查项**：GPU 型号和数量必须与原文一致，原文未提及的不得臆造

### A4 术语与翻译

- [ ] 领域术语使用通行译法（非自创词）
- [ ] 英文缩写首次出现给出全称
- [ ] 抽查 3-5 个非标准英文术语的中文翻译，与领域通行译法核对
- [ ] 无字面直译导致的误译
- [ ] 梵文/拉丁文等非英文术语查证后翻译

### A5 方法描述完整性

- [ ] Pipeline 每个阶段/模块都有描述（不只是名字）
- [ ] 关键设计选择（为什么用这个而非那个）有原文依据

### A6 注释代码来源标注

- [ ] 来自 arXiv source 中被 `%` 注释掉的 LaTeX 代码的事实，是否标注来源
- [ ] 注释代码信息不得写成"论文指出"，应标注"来自论文源码注释，非发表正文"
- [ ] 检查方法：对比 HTML 事实声明与 `sources/<slug>.md` 对应文本，若在 `.tex` 中被 `%` 注释，标记 ⚠️

---

## 维度 B · 完整性（对照已确认大纲逐节核对）

### B1 论文信息

- [ ] arXiv ID、版本号、发表时间
- [ ] 全部作者 + 通讯作者 + 机构
- [ ] 发表 venue（如有）
- [ ] 代码仓库链接（含开源状态）

### B2 核心内容

- [ ] 引言有"为什么值得关注"的判断（不只是摘要翻译）
- [ ] 问题分析有实质性分析（不是复述摘要）
- [ ] 方法核心有完整 pipeline 描述（输入→输出全链路）
- [ ] 训练部分含**训练配置披露表**（10 项基础项：训练数据 / 训练硬件 / 优化器 / 学习率 / Batch size / 训练步数 / 训练时长 / 模型参数量 / 精度格式 / Checkpoint 策略），逐项标注"已披露/未披露"
- [ ] 实验部分含**实验配置表**（6 项基础项：评测数据集 / 评测指标 / Baseline 方法 / **推理硬件** / 推理分辨率 / 推理环境），逐项标注
- [ ] baseline 对比表（含具体数值）
- [ ] 消融分析（每个组件贡献）
- [ ] 局限性分析（不只是论文原文的泛泛描述）
- [ ] 具体可操作的启发建议

### B3 宝藏挖掘

- [ ] "简单但有效"的技巧被记录
- [ ] 超参数消融结果完整（不能只说"掉了点"）
- [ ] 失败案例或"试过没用"的方法被记录
- [ ] 计算成本信息（GPU 数量、训练时间、FLOPs）

### B4 字数与配图

- [ ] HTML 正文总量：常规论文 ≥ 3000 字；复杂系统/综述 ≥ 4000 字
- [ ] 方法核心章节 ≥ 1000 字；实验章节 ≥ 600 字
- [ ] ≥ 3 张关键图片；arXiv 论文优先论文原图，不得用代码绘制图替代可获得的原图
- [ ] 每张图片文件 > 1KB（更小几乎必然是空白图）
- [ ] 图片来源可追溯：`raw/<slug>/figures/<slug>/` 含原始 PDF/PNG
- [ ] 用 `read` 工具视觉抽查 ≥ 2 张图，确认非空白、非裁切错误
- [ ] 综述/导览类：≥ 50% 图片来自论文原图
- [ ] ≥ 1 张代码绘制图（mermaid/jsxgraph），仅作补充示意
- [ ] ≥ 2 个完整数学公式（非综述类）
- [ ] ≥ 1 个 baseline 对比表（含具体数值）
- [ ] ≥ 3 个超参数具体数值

### B5 信息缺口列表

每项：缺失内容 + 是否可从原文补充 + 具体补充内容。

## 维度 C · HTML / 站点规范

### C1 禁止标签（预期为零）

- [ ] `<html>` `<head>` `<body>` `<nav>` `<footer>` `<script>` `<style>`

### C2 frontmatter

- [ ] `title` 非空且符合系列命名规则
- [ ] `description` 一句话
- [ ] `created_at` / `updated_at` 为 `YYYY-MM-DDTHH:mm:ss`
- [ ] `tags` 3-5 个（**硬性上限 5**，超过标记 P1）
- [ ] `aliases` 含 `categories/` 路径
- [ ] `sub_id` 已填且用 `scripts/check-sub-id.py --category <关键词> --suggest` 校验无冲突（步长 10）
- [ ] 含公式时 `mathjax: true`
- [ ] `hero_title` / `hero_sub` / `hero_tagline` 非空
- [ ] `papers` 已填（论文解读必填）
- [ ] `repos` 已填（有开源代码时）
- [ ] `paper_*` 可选字段填写且无正文重复 info-box
- [ ] 系列文章 `hub` 已填

### C3 组件规范

- [ ] 章节使用 `.ch fade-in` + `.ch-title`（不是裸 `<h2>`）
- [ ] 无残留 `#` / `##` markdown 语法
- [ ] 参考来源用 `.sources` 组件，且每条 `data-cite-key`
- [ ] 文章末尾有 `.chapter-nav`，每个 `.nav-card` 带方向 class（`nav-prev` / `nav-hub` / `nav-next`）
- [ ] prev/next 卡片有 `<span class="nav-arrow">`
- [ ] 表格用 `.table-wrap` 包裹，表头 `<th>`

### C4 标签配对（P0）

- [ ] 所有 `<p>` 有对应 `</p>`；所有 `<div>` 有对应 `</div>`；无孤立闭合标签
- [ ] `node lib/lint-html.js <file>` 无 error

### C5 MathJax

- [ ] `mathjax: true`
- [ ] 行内 `\(...\)`、块级 `\[...\]`（按 html-blog 规范）
- [ ] 公式中 `<` 已替换为 `\lt`
- [ ] LaTeX 命令均为 MathJax 支持的标准命令（`\vp`→`\varphi`、`\eps`→`\epsilon`、`\R`→`\mathbb{R}` 等非标准缩写标记 P0）

### C6 图片

- [ ] `.photo` + `.cap` 组件
- [ ] 路径引用实际存在的文件（用 `ls media/images/<slug>/` 验证）
- [ ] WebP 格式
- [ ] 每张图有来源标注（论文原图 / 官方图 / PDF crop / 网络图 / 代码绘制）

### C7 引用

- [ ] 重要事实句使用 `#key#` 语法（非 `(Author, Year)`）
- [ ] `.sources li` 的 `data-cite-key` 与正文 `#key#` 一一对应
- [ ] 无失效链接

### C8 构建

```bash
cd ~/gongshangzheng.github.io && node build.js
```

- [ ] 构建零失败
- [ ] `npm test` 通过

## 问题分级与输出

| 级别 | 判据 | 处理 |
|------|------|------|
| P0 | 事实错误、零图片、标签不配对、build 失败、裸 LaTeX 非标准命令 | **必须修复后才能进 Phase 8** |
| P1 | 字数不达标、tags > 5、来源标注缺失、缺少消融/局限 | 强烈建议修复；不修复须说明理由 |
| P2 | 表述可优化、图片可替换、补充材料 | 可选 |

输出格式：

```text
## 审校报告 · <slug>

### 保真度
✅ 通过项：...
⚠️ 疑似错误：...（原文出处 + HTML 位置 + 建议修正）
❌ 严重错误：...

### 完整性
✅ 通过项：...
❌/⚠️ 缺口：...（缺失内容 + 可补充内容）
统计：总字数 X / 配图 X / 公式 X / 对比表 X / 超参数 X

### HTML / 站点规范
...（每个问题带行号和错误内容）

### 修复优先级
P0：...
P1：...
P2：...

### 总体评分
A / B / C / D + 理由
```

## 按需委派

默认全部由主 agent 完成。仅在以下情况按需委派对应 lane：

| 情况 | 委派 |
|------|------|
| 文章很长，保真度核查需要逐条回原文核对大量数值 | `../subagents/review-fidelity.md` |
| 综述/长文，完整性核对工作量大 | `../subagents/review-completeness.md` |
| 站点规范刚变更，需要独立复核 | `../subagents/review-html-format.md` |

委派时给 lane 提供：HTML 路径、原文路径、change design 路径；lane 只输出问题清单，**不得直接修改 HTML**。
