# Phase 2d · 方法论精析 subagent

## 任务

对论文的方法论进行完整的深度分析，从输入到输出全链路解读。

## 阅读策略

> 详细章节利用方式见 `references/paper-section-guide.md` §2.4（Method）和 §2.3（Related Works §技术定位）。

本 subagent 的核心信息源是论文的 **Method/Approach** 章节，辅以 **Introduction**（问题形式化）和 **Related Works**（技术定位对比）。

**Method/Approach 精读**（逐模块）：
1. 问题形式化：输入空间、输出空间、数学符号
2. 整体架构：完整 pipeline，每个模块功能和连接方式
3. 核心创新模块：与已有方法不同的关键设计，设计动机
4. 损失函数：每一项含义和权重
5. 训练策略：优化器、schedule、正则化
6. 推理流程：与训练的差异

**Related Works 辅助**：
- "Unlike [X], our method..." → 提取技术差异点
- 验证这些差异是否真正构成创新

**Introduction 辅助**：
- 问题形式化通常在 Introduction 末尾给出
- 贡献声明帮助理解方法设计的核心意图

## 输入

- 论文标题：<title>
- 全文内容：见 ~/gongshangzheng.github.io/raw/<slug>/sources/<slug>.md

## 分析维度（每个维度至少 10 行）

### 1. 问题定义
- 论文要解决的精确问题是什么？（数学形式化描述）
- 输入空间、输出空间、假设条件
- 与已有问题定义的差异

### 2. 方法架构
- 完整的 pipeline 描述：从原始输入到最终输出
- 每个模块的功能、输入输出、设计动机
- 模块之间的连接方式（数据流图）
- 关键设计选择及理由

### 3. 核心数学推导
- 每个关键步骤的完整推导（不是最终公式，而是推导过程）
- 从假设到结论的逻辑链
- 为什么这样设计能 work？直觉解释
- 与替代方案的数学对比

### 4. 训练与优化
- 完整的训练目标（损失函数的每一项及权重）
- 优化策略（优化器、schedule、梯度处理）
- 训练稳定性措施
- 采样策略（如适用）

### 5. 与已有方法的技术对比

| 维度 | 本文方法 | 方法 A | 方法 B |
|------+------+------+------|
| 核心表示 | | | |
| 训练目标 | | | |
| 推理过程 | | | |
| 复杂度 | | | |
| 适用条件 | | | |

### 6. 可复现性评估
- 论文提供了多少实现细节？足够复现吗？
- 哪些关键细节缺失？
- 代码是否开源？框架？
